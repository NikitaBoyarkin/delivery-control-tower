## Промпты (по одному на ось)

### Ось A — кластеризация H2

**Objective.** H2 сейчас считается Манн–Уитни по 47 750 city-day как по независимым
наблюдениям (`delivery/hypothesis.py:215`) и бутстрепом по строкам (`:219`). Дата и город —
кластеры: замер аудита даёт ICC=0.049, deff≈9.9, эффективное n≈4 831.

**Success criteria.** `test_h2` возвращает кластерный p и CI (дата-кластерный бутстреп,
город как второй вариант); ICC и design effect попадают в note/отчёт; вывод «H2 отклонена»
сохраняется; добавлен тест, который падает, если кластеризация выключена.

**Constraints.** Не менять формулировку гипотезы и правило вердикта
(`docs/preregistration.md`). Не пересчитывать H1. Строки city-day грузить через
`load_city_daily` (там уже есть `ORDER BY`, нужный для воспроизводимости бутстрепа).

**Scope.** `delivery/hypothesis.py`, `reports/hypothesis_results.csv`, тесты.

**Result contract.** status + `file:line` + числа до/после. Без вопросов; блокер — строкой
`NEED-INFO:`.

### Ось B — фолды прогноза

**Objective.** `REFIT_EVERY = 7` кратен `SEASONAL_PERIOD = 7` (`forecast.py:32-34`), поэтому все
4 origin'а из `make_folds` (`:248-261`) падают на один день недели и step-1 — один и тот же
переход. Плюс h=14 считается с перекрытием: `n_obs=49` при 28 уникальных датах
(`:315-346`), из-за чего конвенция меняет значение 6.25 → 6.01 → 7.84%.

**Success criteria.** Origin'ы распределены по разным дням недели; h=14 разделён на
накопленную ошибку 1..h и чистый lead-14 с явной подписью; артефакт пересобран; README
соответствует.

**Constraints.** `TEST_DAYS = 28` не менять — это окно сравнения с baseline. Метрики
(WAPE/MASE) не переопределять.

**Scope.** `delivery/forecast.py`, `reports/forecast_metrics.csv`, тесты, README-фрагмент.

**Result contract.** status + `file:line` + таблица фолдов до/после.

### Ось C — `degradation_index` без `cost`

**Objective.** Индекс = `(z(slope) + z(weighted_avg_time) + z(cost_per_item)) / 3`
(`bottlenecks.py:237-241`). Треть — по метрике, которую сам проект объявил непригодной
из-за неподтверждённой семантики.

**Success criteria.** Индекс пересчитан без cost-компоненты; cost остаётся отдельной колонкой
для прозрачности; top-10 городов пересчитан и в отчёте сказано, сколько позиций сдвинулось
(по аудиту: без cost в top-10 остаются 4 из 10).

**Constraints.** Колонки CSV не переименовывать — на них смотрят тесты и README.

**Scope.** `delivery/bottlenecks.py`, `reports/bottleneck_cities.csv`, тесты.

### Ось D — децили внутри города

**Objective.** `load_curve` режет децили `pd.qcut` по пулу city-day (`bottlenecks.py:162`) и
считает Спирмена по пулу (`:177`). Дециль 1 — это 131 город с 2–267 позициями/день, то есть
кривая размера города, а не нагрузки. Смешение Симпсона: ρ по пулу −0.092, внутри города
−0.073, на уровне ячейки **+0.107**.

**Success criteria.** Децили считаются внутри города; ρ по пулу и внутри города разведены и
подписаны; `load_curve.csv` пересобран; в отчёте сказано, какой знак остаётся.

**Constraints.** Не менять определение `weighted_avg_time`.

**Scope.** `delivery/bottlenecks.py`, `reports/load_curve.csv`, тесты, README-фрагмент.

## Верификация (producer ≠ verifier)

Агент, писавший ось, не проверяет её. Проверяющий:

```bash
uv run ruff check delivery/ tests/ scripts/
DELIVERY_FORCE_SYNTHETIC=1 uv run pytest -q   # ожидается 84+ passed, 0 skipped
uv run pytest -q                              # профиль реальных данных
```

Плюс по каждой оси — независимый пересчёт числа (pandas/read-only DuckDB), а не чтение
отчёта агента. Ось считается проваленной, если: появился скип, число в CSV не совпадает с
числом в README, или защитный тест проходит и на сломанной версии (mutation control:
откатить фикс в памяти и увидеть падение).
