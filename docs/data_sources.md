# Источники данных

Два исходных CSV не хранятся в репозитории (`.gitignore`). Они не генерируются
кодом: `delivery.etl` только копирует их из `data/raw/` или из папки
`DELIVERY_RAW_SOURCE` в staging. Поэтому воспроизвести проект с нуля можно лишь
при наличии этих файлов.

## Файлы

| Файл | Размер | Строк | SHA-256 |
|---|---:|---:|---|
| `city_day_channel_category.csv` | 78 933 158 B | 550 710 | `961e6f0209c315316e54782dcace5bfadb726b2e421d9559ed5c85d7fda336a0` |
| `orders_sample.csv` | 5 627 020 B | 130 079 | `34e0af20f0c261295ada026e17bb6d3230415a0af64ecf1d9300eba680cf053b` |

Контрольная сумма считается так:

```bash
shasum -a 256 data/raw/city_day_channel_category.csv data/raw/orders_sample.csv
```

## Происхождение

- `city_day_channel_category.csv` — агрегат «день × город × канал × категория»
  за 2022-01-01..2022-06-30 из открытого тестового задания для аналитика
  (Dodo Brands). В исходной папке лежит как `оценка_категорий_4.csv`.
- `orders_sample.csv` — выборка на уровне заказов по двум анонимизированным
  городам из того же задания. В исходной папке — `DA_sql_sample - sql_task.csv`.

Публичной ссылки на архив в проекте нет: файлы задания не публиковались вместе
с репозиторием. Если задание публикуется заново, ссылку и дату скачивания нужно
дописать сюда — иначе читатель не сможет отличить эту версию данных от другой.

## Как положить файлы

```bash
# вариант 1: готовые CSV
cp <путь>/city_day_channel_category.csv data/raw/
cp <путь>/orders_sample.csv data/raw/

# вариант 2: папка с оригиналами — etl скопирует и переименует
export DELIVERY_RAW_SOURCE=/абсолютный/путь/к/папке/задания
uv run python -m delivery.etl
```

`DELIVERY_RAW_SOURCE` по умолчанию — относительный путь `data/raw_source`,
то есть зависит от текущего каталога запуска. Задавайте абсолютный путь.

## Что проверяется по этим файлам

`cfg.EXPECTED_AGG_ROWS = 550_710` и `cfg.EXPECTED_ORDER_ROWS = 130_079`
(`delivery/config.py`) — тесты падают, если число строк в файле другое. Значит
подмена данных на «похожие» ломает проверку намеренно.

## Синтетический стенд

Если исходных файлов нет, пайплайн можно прогнать на полноразмерном
синтетическом двойнике:

```bash
uv run python scripts/make_dummy_dataset.py --validate
```

Он пишет `data/synthetic/` и проверяет контракт (строки, суммы, эффекты).
Числа откалиброваны по опубликованным агрегатам, но это **не исходные данные**:
подробности и таблица калибровки — в [synthetic_data.md](synthetic_data.md).

## Публичная страница

`docs/index.html` — опубликованная версия дашборда на GitHub Pages. Она строится
не из этих CSV напрямую, а из витрин DuckDB в `data/marts/delivery.duckdb`:
`uv run python -m delivery.dashboard_pages` пересобирает страницу из витрин, и
если витрины не собраны, шаг не запустится.
