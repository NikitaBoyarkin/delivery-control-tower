# Предрегистрация H1 и H2

Документ фиксирует, что именно было заявлено до вердикта, каким правилом вердикт
считался и как это правило менялось. Все даты и хеши — из `git`, не из памяти.

## 1. Что это и чего это не доказывает

Формулировки H1/H2, код их проверки и первый артефакт `reports/hypothesis_results.csv`
появились **одним коммитом** — `2af3ea1` от 2026-10-25 00:35:05 +0300 («Initial commit:
delivery operations analytics project»). Данные (`data/raw/*.csv`) уже были в том же
коммите.

Отсюда честная граница: это **регистрация в момент коммита, а не предрегистрация,
отделённая от данных**. Git подтверждает, что 1) тексты гипотез не переписывались после
результата и 2) первая версия правила вердикта существовала до правок, но он не
подтверждает порядок «сначала гипотеза, потом расчёт» внутри одного коммита. Проверить
можно только самим коммитом:

```bash
git show 2af3ea1:delivery/hypothesis.py          # тексты H1/H2 + _supported
git show 2af3ea1:reports/hypothesis_results.csv  # первый артефакт, те же числа
```

## 2. Гипотезы — исходная формулировка (`2af3ea1`, docstring модуля)

| # | Исходный текст | Зарегистрированное направление |
|---|---|---|
| H1 | «the `mp` channel share grows faster than `web` (January vs June daily mix)» | mp выше в июне, чем в январе (June > January) |
| H2 | «weekend delivery time is higher than on weekdays (`mart_city_daily`)» | выходные выше будней (weekend > weekday) |

Обе гипотезы в коде зарегистрированы с `expected_sign = +1` (variant > control) —
см. `delivery/hypothesis.py:124-137`.

Оговорка к формулировке H1: «растёт быстрее, чем web» — тавтология, потому что доля
замкнута в паре mp + web. Фактически проверяется рост доли mp: `test_h1` считает
`mp_share_pair` и формулирует вывод как «доля mp внутри пары mp+web» (`hypothesis.py:149-192`).

## 3. Правило вердикта (текущее, `delivery/hypothesis.py:124-137`)

```
supported ⟺ p_value < α  И  CI не содержит нуля  И  знак эффекта = зарегистрированное направление
```

Как считается каждая часть:

| Элемент | Реализация |
|---|---|
| p-value | критерий Манна — Уитни, `alternative="two-sided"` |
| CI | percentile bootstrap, `BOOTSTRAP_N = 10_000`, `SEED = 42`, `CI_LEVEL = 95` |
| эффект H1 | разница средних дневных долей в п.п. (январь → июнь) |
| эффект H2 | разница медиан city-day в % от медианы будней |
| направление | `ci_low > 0` для `expected_sign = +1` |

Нулевой результат помечается «тенденция, не вывод», значимый эффект обратного знака —
«эффект значим в обратную сторону» (`_verdict_note`, `hypothesis.py:140-146`). Обратный
значимый эффект — это отклонение гипотезы, а не подтверждение.

## 4. α и поправка на множественность

`α = 0.05` на каждую гипотезу, **поправки на множественность нет**. Проверок две (H1, H2),
при Бонферрони порог был бы 0.025. Это зафиксированный выбор, а не забытая деталь: обе
проверки независимы по данным (канальный микс против времени доставки), и проект
предпочитает читать каждую как отдельную заявку.

## 5. История изменения правила вердикта

| Коммит | Дата (+0300) | Правило |
|---|---|---|
| `2af3ea1` | 2026-10-25 00:35:05 | `p < α` И CI не пересекает ноль; **знак не проверялся** — значимый эффект в любую сторону считался подтверждением |
| `3419c20` | 2026-10-25 03:37:20 | добавлен `expected_sign`: требуется зарегистрированное направление (+1 для H1 и H2). До этого коммита действовало правило из строки выше |
| `6cfd76e` | 2026-10-26 22:55:53 | правило не менялось; добавлен `ORDER BY city_name, date` в `load_city_daily`, чтобы бутстреп-CI не зависел от физического порядка строк |

Правило ужесточили **после** того, как увидели результат H2, — это нужно назвать прямо.
Ужесточение работает против проекта: значимый обратный эффект H2 оно превращает из
«подтверждена» в «отклонена». В том же коммите `3419c20` исправлен вес `avg_time` в
витринах (`SUM(qty * avg_time) / SUM(qty)` вместо `AVG(avg_time)`), из-за чего H2
сменилась с нуля (p = 0.617, −0.02%) на значимый эффект −0.93% в обратную сторону.

## 6. Где считается канонический H1

| Путь | Роль |
|---|---|
| `delivery/hypothesis.py` → `reports/hypothesis_results.csv` | **канонические** H1 и H2: Манн — Уитни по 30/31 дневной доле |
| `scripts/ab_test_analyzer.py` → `reports/ab_test_metrics.csv` | **альтернативная спецификация** H1: z-тест по пулированному `qty` (единица — позиция, не день). Числа отличаются (+5.791 п.п. против +5.699 п.п.) и H1 проекта не заменяют |

При расхождении цифр источник истины — `hypothesis.py`.
