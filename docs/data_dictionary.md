# Словарь данных

Источник — агрегат «день × город × канал × категория» за 2022-01-01..2022-06-30
(550 710 строк), собранный в `data/marts/delivery.duckdb` модулем `delivery.marts`.
Семантика ниже проверена по числам на этом датасете; где проверки нет — это явно указано.

| Колонка | Смысл | Как проверено | Ограничение |
|---|---|---|---|
| `tickets` | Число чеков (заказов), не обращений в поддержку | `SUM(qty)/SUM(tickets) = 1.736` (позиций на заказ); `SUM(clients_qty)/SUM(tickets) = 0.94`; итого `SUM(tickets) = 33 167 293` | Название историческое; в отчётах подписывается «Заказы» |
| `qty` | Число позиций (блюд) | `SUM(qty) = 57 576 550`; отношение к `tickets` даёт правдоподобный размер заказа | Не путать с числом заказов |
| `clients_qty` | Уникальные клиенты в ячейке (день × город × канал × категория) | `SUM(clients_qty)/SUM(tickets) = 0.94` | Уникальность считается внутри ячейки; суммирование по ячейкам не даёт уникальных клиентов за период |
| `cost` | Денежная метрика источника | `SUM(cost)/SUM(tickets) = 138.9` | **Валюта не подтверждена**, и то, что это выручка, не подтверждено; в подписях — «cost, ед. источника» |
| `avg_price` | Средняя цена из источника | `AVG(avg_price) = 221.8`, но `SUM(cost)/SUM(tickets) = 138.9` — величины не согласуются | Семантика не подтверждена; **в расчётах не используется** |
| `avg_time` | Время доставки, минуты | Используется как время доставки в `mart_city_daily` и `mart_delivery` | Среднее по ячейке; при агрегации за период взвешивается по `qty` |
| `rto` | Метка операционного цикла (`rto`) | Значения присутствуют в источнике; доля взвешивается по `qty` в `mart_delivery` | Смысл единиц не подтверждён; не интерпретировать как долю или процент без проверки |
| `rto_do` | Метка операционного цикла (`rto_do`) | Аналогично `rto` | Смысл единиц не подтверждён |
| `items_per_order` | Позиций на заказ = `SUM(qty) / NULLIF(SUM(tickets), 0)` | Среднее по `mart_delivery` ≈ 1.74; совпадает с `SUM(qty)/SUM(tickets)` | Производная метрика; считается на гранулярности строки витрины |
| `weighted_avg_time` | Среднее время доставки, взвешенное по `qty` | `SUM(qty * avg_time) / SUM(qty)` | При агрегации за период нельзя брать `AVG(...)`, только повторное взвешивание по `qty` |
| `cost_per_item` | `SUM(cost) / NULLIF(SUM(qty), 0)` — cost на **позицию** | Совпадает с определением в `delivery.marts` | Валюта не подтверждена. Это не `cost_per_order` |
| `cost_per_order` | `SUM(cost) / NULLIF(SUM(tickets), 0)` — cost на **заказ**; метрика дашборда KPI «Стоимость заказа» | `SUM(cost)/SUM(tickets) = 138.9`; в `mart_delivery` колонки нет, она считается в `delivery.dashboard` | Отличается от `cost_per_item` примерно в 1.74 раза (позиций на заказ); валюта не подтверждена |

## Чего в витринах нет

- `tickets_per_100` удалена: `100 * SUM(tickets) / SUM(qty)` — это доля чеков к позициям,
  а не «тикетов на 100 заказов». Правильная производная — `items_per_order`.
- Метрики «выручка» и валюты `₽` не выводятся: `cost` не подтверждён как выручка.
